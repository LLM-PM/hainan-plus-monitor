## 评审结论摘要

拆成两个独立问题，答案不同：

- **作为工程方案文档**：合格，明显高于同类个人工具平均水平，可直接作为开发基线。**8/10**
- **作为产品是否值得投入**：可行性低，端到端成功概率约 **20–30%**。**3/10**

三个决定性风险：

1. **入口大概率已收进原生 App**（估 55–65%）。方案自己引的资料说明飞飞乐关停、权益迁入海航 App，这个迁移方向本身就是信号。一旦如此，方案第 04 章两条浏览器路径同时作废。
2. **只验证了"能不能查"，没验证"能不能捕获"**。199 元票秒级放出秒级被抢；30 分钟轮询对存活 2 分钟的机会，捕获率约 6.7%。这是决定项目值不值得做的唯一数字，全文未估算。
3. **账户风控代价完全未建模**。PLUS 卡是付费资产，封禁不可逆无申诉；而方案设定的 700 次/天 ≈ 每 2 分钟一次、连续 7–14 天，在任何风控系统里都是显著离群点。

另有一处内部数学矛盾：14 键 × 30 分钟 = 672 次/天对日预算 700（余量 28），每小时 28 次对限额 30（余量 2），而第 07 章每次机会还要 60 秒复查一次——余量必然击穿，但 A10 却要求 ≥95%/≥90%。**这两组数字不相容。**

## 2026-09-10 预验证发现（无需登录部分）

- **官方参考航线表已过期**：覆盖 2025/12/31–2026/2/16，发布于 2025/12/29，至今未更新；未找到新版本。
- **公开路径上找不到权益票查询入口**：`m.hnair.com/cms/me/plus/` 是零链接的纯静态营销页，讲的是会员卡权益包（改期/代金券/98折/积分），不是 199 元权益票。
- **由此产生新问题**：航线表停更 + 飞飞乐 App 关停，"该产品当前是否仍在运营"本身成了未经证实的前提。已作为 **A0** 加入 P-1 清单最前面。
