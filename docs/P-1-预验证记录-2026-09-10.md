## 2. 公开路径上未找到权益票查询入口

`https://m.hnair.com/cms/me/plus/` — 标题 `PLUS会员_海南航空`，9.2 KB。

页面内容描述的是**会员卡权益包**：免费改期、代金券（￥200×1 / ￥100×1 / ￥50×3）、
尊享折扣（额外 98 折，不含会员日客票等特价产品）、20% 额外积分。

**这不是 199 元权益票的查询或兑换入口。** 该页：

- 链接数 **0**
- 无 `location.href` 跳转、无 `hnair://` scheme、无 openApp / UniversalLink 痕迹

即一个纯静态营销页。在浏览器可达的公开路径上，没有发现通往权益票查询的入口。

## 3. 浏览器自动化在本环境不可用

同一时间窗口、同一 URL（`https://www.hnair.com/`）的对照：

| 客户端 | 尝试次数 | 结果 |
| --- | --- | --- |
| curl（默认 UA） | 3 | 3 × HTTP 200 |
| curl（Chrome UA） | 3 | 3 × HTTP 200 |
| curl `--http1.1` | 2 | 2 × HTTP 200 |
| curl `--http2` | 2 | 2 × HTTP 200 |
| **Chromium / Playwright** | **5** | **5 × `ERR_CONNECTION_RESET`** |

curl 全通、Chromium 全断，且非协议版本问题。容器内无法区分根因是
"站点按 TLS 指纹拦截浏览器" 还是 "代理中继不兼容 Chromium 握手"——
但两种解释都指向同一个操作结论：**P0 的浏览器验证必须在用户自己的设备与网络上做。**

`m.hnair.com` 根域在本环境亦频繁重置（代理侧记为 `ws_closed_mid_exchange`），
仅 CMS 静态页可稳定取得。

## 4. UA 过滤假设已证伪

初次观测出现过 "默认 UA 重置、Chrome UA 200" 的现象，看似 WAF 按 UA 过滤。
重复三轮对照后**两者均为 200**，该假设不成立。原观测属偶发重置造成的巧合，
已在此明确记录以免误导后续验证。
